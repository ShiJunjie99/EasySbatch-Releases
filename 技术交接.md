# EasySbatch public architecture handoff

This handoff is safe for a public repository. The desktop Beta contains one
owner-approved exception: host `10.158.132.77` and its cluster-wide shared
environment loading steps are a public product preset. User-specific usernames,
home paths and environments remain excluded. Other real addresses, catalogs,
databases, logs and integration evidence belong in the ignored
`deployment-private/` area or in an administrator-owned directory.

The public application consists of a server-side FastAPI/Worker/Harness and a
user-side Launcher. `ClusterProfile` stores only an id, display name, SSH host
and port. The local username and known-hosts file are user/deployment settings;
passwords and private keys remain with system OpenSSH.

The server scans projects, creates bounded AI requests, parses provider output,
validates schema/evidence/provenance, prepares `JobSpecDraft`, and controls
Slurm submission. The Launcher binds the exact WebSession/Worker session and,
when `local_user_provider` is selected, calls the fixed DeepSeek endpoint with
the current user's OS-stored key. The key never crosses SSH, enters Worker,
Broker, WebSession, SQLite, JobSpec, Slurm environment, logs or artifacts.

The public examples use `cluster.example.edu`, port 22, synthetic users, and
fake software paths. Real Server Catalogs and workspace discovery are private
deployment inputs. M10-B5/B5B/B5C remain historical experimental transport
research; M10-B7 is the simplified local-provider design. M10-C has not begun.

Run `.venv/bin/python -m pytest -q` for the offline regression suite. Native
launcher builds run in the tag-gated GitHub Actions workflow. Repository
visibility and GitHub Release publication require the checklist in
`docs/OPEN_SOURCE_RELEASE_CHECKLIST.md` and explicit human approval.
