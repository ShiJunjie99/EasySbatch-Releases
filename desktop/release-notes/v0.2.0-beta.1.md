# Beta EasySbatch v0.2.0-beta.1

This Beta moves the remaining core Web workflows into the native desktop
product while keeping final Slurm submission user-controlled.

## Added

- in-app SSH login with separate server IP and port fields, Linux username, and
  an operating-system-vault password bound to the last successful account;
- in-app SHA-256 server fingerprint confirmation with no terminal setup step;
- automatic shared environment and software catalog when the IP is
  `10.158.132.77` and the port is `3088`;
- safe empty catalog and no-command environment fallback for other hosts;
- manual New task panel with environment, software, resource, input, output,
  preparation-step, and launcher controls;
- fresh all-partition resource recommendation with an explicit evidence notice;
- user-driven, read-only remote directory picker limited to 500 metadata rows;
- bounded read-only remote project scan, with user-bound paths and no upload;
- persistent Smart drafts with `NEEDS_INPUT`, `READY_TO_SAVE`, revision checks,
  and a fresh remote fingerprint check before saving;
- memory and walltime recommendations only when an exact verified rule or a
  matching project declaration supplies inspectable evidence;
- immutable script-preview digest: changing a draft invalidates its approval;
- full JobSpec, evidence, script path, log path, and failure detail in Task history;
- stricter assistant sequence: scan, list profiles/catalog, validate, recommend,
  then create or revise a preparation that only the user can finalize.
- signed packages check the public EasySbatch GitHub Releases `beta` channel
  and install an accepted update before restarting the application;
- maximum installer compression, selective release-file staging, and cloud size
  reports that separate final installers from Electron/Node/DSH build content;

## Safety and current limitations

- The model cannot finalize or submit jobs, run Shell, choose remote paths, edit
  files, use the Web, or select physical compute nodes.
- Remote scanning reads only bounded relevant text and never uploads or writes
  project content.
- SSH passwords are passed only through the local in-memory protocol and stored
  at rest only by Windows Credential Manager or macOS Keychain; plaintext
  product files never contain them.
- Unsigned test installers carry no update feed. Formal packages are built from
  a protected release environment and must pass Authenticode or Developer ID,
  notarization, updater-metadata, checksum, and provenance checks before the
  prerelease is created. Model-credential keychain migration remains future
  work.
- Intel macOS is not included; packages target Windows x64 and Apple Silicon.

Build and package validation must be completed by GitHub Actions. Local source
checks are not evidence that either native installer builds successfully.
